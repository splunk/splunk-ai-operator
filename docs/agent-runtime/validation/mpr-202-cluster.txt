### 11. Root cause of the churn in section 9 (bisected on the live platform, then restored)
  3e4bb99 (the mainline merge just before MPR-189): +0 Deployment generations in 3 minutes
  955dd11 (MPR-189, "bound schema Jobs and make replay safe"): +1272 in 3 minutes
A watch of the SAIA Deployment under 955dd11 saw 48 versions in 20 s with an identical spec. The
loop is in the metadata annotations: the SAIA and SLIM Deployment mutators replace
metadata.annotations wholesale, dropping deployment.kubernetes.io/revision. The Deployment
controller restores it, and the API server bumps a Deployment's generation on any annotation
change, so each write costs two generations and a status update (observedGeneration). Before
955dd11, the controller's global event filter needed a generation, label or annotation change on
the event, so that status-only update was filtered out. 955dd11 added DeploymentChangedPredicate
(status changes) to the global filter, so each status update now wakes the AIService reconcile,
which writes again. AgentRuntime has the same mutator shape but was fixed in 488a9a2 (it keeps the
revision annotation); SAIA and SLIM were not. Restored afterwards: operator spec, ClusterRoles and
CRDs identical to the backups, +0 generations in 60 s, live checkpoints unchanged, all Ready.
